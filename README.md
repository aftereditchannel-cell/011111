## 🔗 ← اول این را عوض کن: لینک‌ها

هر دو دکمهٔ «ثبت‌نام در میتینگ» و «عضویت در لیبل» فعلاً به یک **لینک نمونه** وصل‌اند.
فایل `assets/js/core.js` را باز کن، حدود **خط ۱۱۲۷** این بخش را ببین:

```js
var LINKS = {
  rsvp: {
    url:   "https://t.me/011meeting",   // ← آدرس واقعی را اینجا بگذار
    label: "ثبت‌نام در میتینگ",
    hint:  "ثبت‌نام از طریق تلگرام انجام می‌شود"
  },
  label: {
    url:   "https://t.me/011meeting",   // ← آدرس واقعی را اینجا بگذار
    label: "عضویت در لیبل ۰۱۱",
    hint:  "برای ارسال نمونه‌کار و درخواست عضویت"
  }
};
```

فقط `url` را عوض کن — **همین یک فایل**، و هر ۵ جایی که این دکمه‌ها ظاهر می‌شوند
خودکار به‌روز می‌شوند:

۱. کارت میتینگ بعدی (صفحهٔ اصلی)
۲. صفحهٔ جزئیات هر میتینگ
۳. دیالوگ صفحهٔ ثبت‌نام
۴ و ۵. پایین منوی کشویی

می‌توانی `label` (متن دکمه) و `hint` (توضیح زیرش) را هم عوض کنی.

### ✏️ عوض کردن محتوای میتینگ

در `assets/js/core.js` دنبال `meetings: [` بگرد (حدود خط ۲۵۷):

```js
{ id:"m1", title:"میتینگ رپ آمل", venue:"آمل، مازندران",
  date:"2026-08-14T20:00:00",          // تاریخ میلادی معادل ۲۳ مرداد
  going:0, cap:200,
  soon:true,                            // ← تاریخ هنوز قطعی نیست
  whenLabel:"۲۳ یا ۲۴ مرداد ۱۴۰۵",     // ← متنی که نمایش داده می‌شود
  ... }
```

**نکتهٔ مهم — `soon`:**
وقتی `soon: true` باشد، به‌جای تاریخ و ساعت دقیق، متن `whenLabel` نمایش داده
می‌شود و «روز مانده» با `~` (تقریبی) می‌آید. وقتی تاریخ قطعی شد:

۱. `date` را دقیق بگذار
۲. `soon: true` و `whenLabel` را **حذف کن**
۳. عدد `SEED_VERSION` را یکی زیاد کن (پایین‌تر توضیح داده شده)

### ⚠️ بعد از هر تغییر در داده

مرورگر دادهٔ قبلی را ذخیره کرده. برای اینکه تغییرات دیده شود، در
`assets/js/core.js` این عدد را **یکی زیاد کن**:

```js
var SEED_VERSION = 5;   // ← ۶ کن
```

با این کار دادهٔ ذخیره‌شده در مرورگر همهٔ کاربران خودکار به‌روز می‌شود.
(یا کاربر می‌تواند از **تنظیمات ← ریست کامل داده‌ها** استفاده کند)

## 📡 مدیریت خطای شبکه

اگر سرور ساندکلود پاسخ ندهد (نت ضعیف یا فیلترینگ)، هر بخش به‌جای
صفحهٔ خالی، یک بلوک خطا نشان می‌دهد:

- پیام واضح «... بارگذاری نشد»
- هشدار: «در بعضی مواقع سرور ساندکلود **بدون VPN** پاسخ نمی‌دهد»
- دکمهٔ **↻ تلاش مجدد** که کش را پاک و صفحه را دوباره بارگذاری می‌کند

تشخیص خطا حداکثر ۹ ثانیه طول می‌کشد.

| 🙍 پروفایل | `profile.html` |
| 🔔 اعلان‌ها | `notifications.html` |
| 🔐 ثبت‌نام | `auth.html` (+ دکمه‌های لینک بیرونی) |

سه صفحه هم **ریدایرکت** می‌شوند: `meetings.html` → `index.html` ·
`player.html` → `music.html` · `story-view.html` → `stories.html`

**رفتار قفل:**
- بلور **بسیار سبک** (۱.۴ پیکسل) — محتوا کاملاً پیداست
- کارت دیالوگ **نیمه‌شفاف و شیشه‌ای** — محتوای پشتش دیده می‌شود
- متن دیالوگ سایه دارد تا روی هر پس‌زمینه‌ای خوانا بماند
- کلیک روی محتوای پشت بلور کار نمی‌کند
- هدر و منوی پایین سالم می‌مانند؛ تب‌های قفل‌شده کم‌رنگ‌اند با نشان 🔒
- داخل هر دیالوگ: «📅 دیدن میتینگ‌ها» + «✅ ثبت‌نام در میتینگ ↗»

## 🔓 باز کردن یک بخش

**دو جا** باید تغییر بدهی:

### ۱) حذف دیالوگ از خود صفحه
فایل موردنظر را باز کن و این تکه را از انتهای اسکریپت **پاک کن**:

```js
A.lockPage({
  icon: "⚔️",
  title: "بخش بتل‌ها هنوز فعال نشده",
  text: "..."
});
```

### ۲) برداشتن نشان 🔒 از نویگیشن
در `assets/js/core.js` (حدود خط ۱۱۲۵):

```js
var LOCKED = ["battles", "profile", "notifications", "auth",
              "rank", "gangs", "chat", "search", "upload"];
```

کلید موردنظر را حذف کن. برای باز کردن همه: `var LOCKED = [];`

### ۳) برگرداندن ثبت‌نام داخلی (اختیاری)
اگر `auth` را باز کردی و خواستی ثبت‌نام داخل سایت دوباره کار کند،
در `core.js` تابع `needAuth` را به حالت قبل برگردان:

```js
function needAuth(msg) {
  toast(msg || "برای این کار باید وارد شوی.", "err");
  setTimeout(function () { location.href = "auth.html"; }, 900);
}
```

## 🎨 تنظیم شدت بلور

در `assets/css/style.css`:

```css
.is-locked{
  filter: blur(1.4px) saturate(1) brightness(1);   /* بلور محتوا */
}
```

و شفافیت کارت دیالوگ:

```css
.lockcard{
  background: linear-gradient(160deg, rgba(26,26,36,.66), rgba(12,12,18,.74));
}
```

عدد `.66` / `.74` را بالا ببری کارت مات‌تر می‌شود، پایین بیاوری شفاف‌تر.
